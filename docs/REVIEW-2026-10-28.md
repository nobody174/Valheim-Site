Read after `CLAUDE.md`. Earlier reviews: `REVIEW-2026-10-27.md`, `REVIEW-2026-10-27-2.md`,
`NEXT-STEPS-2026-10-27.md`. This review was report-only: no code or data was changed.

Method: pulled `main`; ran validate, typecheck, lint, tests and build; scripted consistency audits

and DATA_SOURCES. Not done: a play-through (so nothing here is "in game"), and a check of the

the last review landed. The main risk is no longer looks or engineering: it is **claimed trust
versus earned trust**, and **scope versus the ability to keep it correct**.

## 2. What is genuinely good (keep it)

- Packages 1 to 5 done: station build costs, hoard from recipes with a neutral "Gear" badge,
  dropped-recipe report with reasons, typo-tolerant search with aliases, item page ordered
  answer-first, Fenris/Cultist/trinkets/Wolf Skewer, Mistlands and Ashlands added.
- Checks green: validate, typecheck, lint, 318 tests, build. No console errors on 32 routes.
  No sideways scroll at 390px.
- Data is internally consistent: no CamelCase prefab ids in text, no duplicate names, armor sets
  equal declared size, no zone mismatches, tiers rise monotonically by zone.
- Entry chunk 1,124 kB raw / 236 kB gzip (was 1.1 MB gzip). Auto-update fixes stale versions.
- Data version and review date visible on a phone ("Data: Steam build 25909357, reviewed ...").
- `fch.ts` is defensive: bounds checks (`need`), count caps, version refusal, read-only picker.
- Home hero and zone cards are the first screen that feels like the game.

## 3. Findings

Severity: **High** (breaks trust or the core promise), **Medium**, **Low**. IDs continue from
review 2 (F1 to F22), so this list starts at G1.

### Data and trust

- **G1 (High): Zero in-game verification, but the roadmap says v1.0.** 0 of 1,300+ entries are
  `in-game`. Items 376 cross-checked / 69 unverified; creatures 44 / 7; bosses 7 unverified.
  "Extracted from my own game files" is strong, but nobody has seen these values work in game.
  Either do a real spot-check pass or call the release a beta.
- **G2 (High): Mistlands and Ashlands data is unverified and unplayed.** The owner has not
  played these zones yet, so no one can review the values. They are labelled, but the zone cards
  look as finished as Meadows.
- **G3 (Medium): Hand-written values still rest on guides.** Dragon and Goblin King summons are
  "curated from guides". They have per-value tags, which is good, but a wrong summon cost on a
  boss page is the sort of error that destroys trust.
- **G4 (Medium): Items with no source remain:** Fenris Hair, Fenris Claw, Ymir Flesh, Carrot
  Seeds, Elder Bark. Fenris items may well drop from creatures that exist in the data now (check
  Fenring/Cultist drop tables again after the Mistlands work).
- **G5 (Medium): Cauldron level 6 looks unreachable** (Smoker needs Bloodgold/Timberwood). It is
  more likely a data gap or a station-upgrade modelling gap than a game rule. Check it.
- **G6 (Medium): `docs/DATA_SOURCES.md` is stale.** The register row for items and bosses still
  says "Meadows to Plains; Mistlands and Ashlands not added yet". The spot-check list covers 30
  entries against 1,300+.
- **G7 (Low): 69 unverified items, 7 unverified creatures, no list of why.** Add the reason per
  entry (for example "no recipe in files", "name override") so unverified means something.
- **G8 (Low): `lastReviewed` says 2026-10-28.** Make sure that date means a human reviewed data,
  not a rebuild. A rebuild should not move it.
- **G9 (Low): Materials in the data that nothing uses.** Review "never used" items and mark why
  (cosmetic, creative only, cut content).

### Scope and maintainability

- **G10 (High): Scope explosion.** About 36 PRs in a day; 20+ pages (planner, optimizer, graph,
  character reader, checklist, progression, commands, updates, profile...). Every page is another
  place where a game patch can make data silently wrong. Features are being added faster than
  trust is being earned.
- **G11 (Medium): No automatic patch-day check.** There is `UPDATE_AFTER_PATCH.md`, but nothing
  detects that the installed game build differs from `data/meta.json` `gameVersion`, or diffs
  extracted data between builds.
- **G12 (Medium): The extractor needs the owner's game install.** Only one person can refresh
  the data. That is fine for a personal site, but document the exact steps and make a dry-run
  mode that diffs against current JSON.
- **G13 (Low): 4 low `npm audit` findings** (deepmerge via vite-plugin-pwa/workbox). Not
  exploitable on a static site; record that decision in the docs so it stops being noise.
- **G14 (Low): Shared origin** `nobody174.github.io` with other projects (F20 still open).
  Keep the `vcs:v1:` prefix, store nothing sensitive, and note it in ARCHITECTURE.md.

### Mobile and UX

- **G15 (High): Tap targets on list pages.** Under 44px interactive elements at 390px: Items
  444 of 481, Checklist 1,861 of 2,258, Building 167 of 596, Food 68 of 105, Creatures 179 of 212.
  For a phone-beside-the-keyboard tool, the longest pages are the hardest to tap.
- **G16 (Medium): Mobile header clips the search placeholder** ("Search (Ctrl+"). The keyboard
  hint is meaningless on touch.
- **G17 (Medium): Top navigation tabs are cut off** ("Buil...") with no scroll cue. A bottom
  tab bar was already in the backlog (F13).
- **G18 (Medium): "Ready to work offline" toast covers content** and the data-version footer at
  the bottom of item pages. Auto-dismiss it and put it at the top.
- **G19 (Medium): Commands page fails axe** (`scrollable-region-focusable`, serious): a
  scrolling code or table area cannot be reached by keyboard. About 11 tiny-text elements there;
  Places has about 10.
- **G20 (Medium): Crafting graph is an empty black page** until an item is chosen. Give it a
  default (for example the last viewed item, or "Iron Sword") and a 390px layout check.
- **G21 (Medium): Very long pages render everything at once.** Recipes counts about 2,500
  interactive elements and Checklist about 2,250. No list virtualisation or grouping, so older
  phones will stutter.
- **G22 (Low): Zone cards show "0 / 65 found"** for a fresh visitor, which reads like a failure.
  Frame it as progress to start (for example "Not started").
- **G23 (Low): Home "Press / on any page to search"** is desktop copy shown on mobile.
- **G24 (Low): Link row on the item page** (Plan this, Upgrade calculator, Crafting graph,
  Compare) wraps into two ragged lines on a phone. Make it a compact action bar.
- **G25 (Low): Precache is about 3.5 MB.** Fine on Wi-Fi, but say so before the offline toast,
  and make sure icons are not all precached on first load.

### Design

- **G26 (Medium): Zone tint is on banners only.** Good restraint, but the rest of a zone's pages
  still look identical. A thin zone-coloured top border on list pages would carry the "where am I
  in the game" feeling.
- **G27 (Low): Typography is solid but the headline is the only place with game character.**
  Item and creature cards are clean but generic (rounded dark card plus gold button).
- **G28 (Low): Gold link underline plus gold buttons plus gold headings** compete; links and
  actions look the same.

## 4. Roadmap to 10/10 (solutions, in priority order)

### Work package A: Earn the trust (data trust 6 to 9.5). Biggest lever.

1. **Play-test spot-check pass.** Make a printable checklist (generated from the data) of about
   30 entries per zone: 10 weapons or armor (damage, armor, durability), 10 recipes (inputs,
   station, level), 5 foods (HP, stamina, duration), 3 creatures (HP, drops), 2 boss summons.
   Mark each `in-game` only after seeing it. Target: every Meadows to Plains boss, every weapon
   in the rankings, every food.
2. **Add a verification dashboard** at `/updates` or `/profile`: counts per level per zone, so
   "0 in-game" is visible and moves. Make it the site's honesty page.
3. **Rename the label** `cross-checked` to something plainer such as "from game files" (the item
   page already says "From game files"; align data and UI).
4. **Resolve the five sourceless items** (G4) and the cauldron question (G5) from raw dumps; if
   truly sourceless, say "no drop found in game files" instead of an empty field.
5. **Stop the label drifting:** a test that fails if `lastReviewed` changes without a changed
   `verified` count or a reviewer note.
6. **Mistlands and Ashlands:** gate them behind a visible "Not yet played by the owner" banner
   until step 1 is done for those zones.

### Work package B: Cut scope risk (maintainability 5.5 to 9)

1. **Feature freeze** for two weeks: only bug fixes, verification and mobile.
2. **Tier the pages in docs** (core: search, items, recipes, bosses; useful: planner, rankings,
   progression; experimental: graph, optimizer, character reader). Mark experimental pages with
   a small "Beta" tag in the sidebar.
3. **Patch-day tooling:** `npm run patchcheck` compares the installed Steam build number with
   `meta.json` and runs the extractor to a temp folder, then prints added, removed and changed
   entries (a readable diff). Add the result to `UPDATE_AFTER_PATCH.md`.
4. **Snapshot tests** on a handful of computed values (DPS, ratings, totals) so a data refresh
   that moves numbers shows up in review.
5. **Dependabot or a monthly reminder** for dependencies; record the 4 low audit findings as
   accepted.

### Work package C: Phone-first lists (mobile 6 to 9)

1. **Row tap targets:** `min-height: 44px` on list rows and chips under `@media (pointer: coarse)`;
   make the whole row the link, not just the name.
2. **Mobile bottom tab bar** (Home, Search, Items, Planner, More). Remove the clipped top tabs.
3. **Header:** shorter placeholder on touch ("Search"), hide the keyboard hint on touch.
4. **Toasts:** auto-dismiss in 4 s, render at top, never over the footer or content.
5. **Virtualise or group long lists** (Recipes, Checklist): collapse by zone and station, render
   only the open group; add "Jump to zone".
6. **Fix Commands** (focusable scroll region: add `tabindex="0"` and a label, or wrap the table),
   and raise the tiny text (Commands and Places) to at least 12px.
7. **Graph:** default item, a "fit to screen" button, and a 390px layout with the controls
   collapsed.
8. **Make the axe, tap-target and overflow audit part of CI** (Playwright script from the review
   scratch folder, checked in under `tools/qa/`), failing on new axe violations.

### Work package D: Design to a 9 (looks 7.5 to 9, Valheim feel 6.5 to 9)

1. **Zone themes on every zone-bound page**, using `data-zone` (a coloured top rule, a banner
   strip, tinted focus rings), not whole-page tints.
2. **Distinct action vs link styling:** links get a subtle underline only; primary actions get
   the parchment button.
3. **Collectible feel for bosses and trophies:** stamped "found" state, trophy silhouette until
   found, progress ring per zone on the checklist.
4. **Empty and first-run states** with Valheim-flavoured copy that carries no data (for example
   the graph, zone cards at 0, favourites). Never put jokes in tooltips that carry data.
5. **A short first-visit tour** (three tooltips): search, current zone, hoard badge.
6. **Light polish list:** icon.svg and maskable PWA icon, 404 page in theme, print stylesheet for
   the checklist, a high-contrast option, and a "reduce motion" respect for the hero.

### Work package E: Docs and housekeeping (quick wins)

1. Refresh the DATA_SOURCES register row and extend the spot-check list to every zone.
2. ROADMAP: replace "v1.0 released" with the honest state until package A step 1 is done.
3. Document the shared-origin decision (G14) and the audit decision (G13).
4. Record the measured baselines (below) in ROADMAP and re-measure after each package.
